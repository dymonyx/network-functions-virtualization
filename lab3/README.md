# Лабораторная работа №3. Настройка VXLAN в GNS3 на базе двух маршрутизаторов SONiC

## Создание топологии

В GNS3 был создан новый проект, в котором была собрана сеть из двух маршрутизаторов SONiC, двух коммутаторов и двух хостов VPCS.

Топология сети:

```text
PC1 — Switch1 — R1 (SONiC) — R2 (SONiC) — Switch2 — PC2
```

Для соединения маршрутизаторов была выбрана сеть `10.10.0.0/24`, а для хостов — логическая сеть `192.168.10.0/24`.

### Сеть Underlay

- R1 Ethernet4: `10.10.0.1/24`
- R2 Ethernet4: `10.10.0.2/24`

### Сеть Overlay

- PC1: `192.168.10.11/24`
- PC2: `192.168.10.12/24`
- VLAN: `10`
- VNI: `1000`
- Подключение хостов к маршрутизаторам: `Ethernet0`

Таким образом, два локальных сегмента VLAN 10 должны объединяться через VXLAN-туннель между маршрутизаторами.

## Подключение к SONiC

После запуска виртуальных маршрутизаторов были открыты их консоли.

Для входа использовались стандартные учётные данные SONiC:

```text
Login: admin
Password: YourPaSsWoRd
```

После авторизации было проверено состояние интерфейсов:

```bash
show interfaces status
```

## Настройка сети Underlay

На обоих маршрутизаторах были удалены заводские IP-адреса с интерфейсов `Ethernet0` и `Ethernet4`, чтобы они не мешали настройке VLAN и новой подсети:

```bash
sudo config interface ip remove Ethernet0 10.0.0.0/31
sudo config interface ip remove Ethernet4 10.0.0.2/31
```

На R1 интерфейсу `Ethernet4` был назначен адрес:

```bash
sudo config interface ip add Ethernet4 10.10.0.1/24
```

На R2:

```bash
sudo config interface ip add Ethernet4 10.10.0.2/24
```

После настройки были проверены IP-адреса интерфейсов:

```bash
show ip interfaces
```

Для проверки связи между маршрутизаторами использовалась команда `ping`:

На R1:

```bash
ping 10.10.0.2
```

На R2:

```bash
ping 10.10.0.1
```

## Настройка VLAN

На каждом маршрутизаторе была создана VLAN 10:

```bash
sudo config vlan add 10
```

Интерфейс `Ethernet0`, соединённый с локальным коммутатором и хостом, был добавлен в VLAN 10 без тегирования:

```bash
sudo config vlan member add -u 10 Ethernet0
```

Параметр `-u` означает `untagged`, поскольку хосты VPCS передают обычные Ethernet-кадры без VLAN-тегов.

Настройка VLAN была проверена:

```bash
show vlan brief
```

## Настройка VXLAN

На R1 был создан VXLAN-интерфейс `Vxlan1` с исходным IP-адресом `10.10.0.1`:

```bash
sudo config vxlan add Vxlan1 10.10.0.1
```

После этого VLAN 10 была сопоставлена с VNI 1000:

```bash
sudo config vxlan map add Vxlan1 10 1000
```

Для указания удалённого маршрутизатора в конфигурацию был добавлен IP-адрес R2:

```bash
sudo sonic-db-cli CONFIG_DB HSET 'VXLAN_TUNNEL|Vxlan1' dst_ip 10.10.0.2
```

На R2 были выполнены аналогичные команды:

```bash
sudo config vxlan add Vxlan1 10.10.0.2
sudo config vxlan map add Vxlan1 10 1000
sudo sonic-db-cli CONFIG_DB HSET 'VXLAN_TUNNEL|Vxlan1' dst_ip 10.10.0.1
```

Для проверки созданных VXLAN-интерфейсов и сопоставления VLAN с VNI использовались команды:

```bash
show vxlan interface
show vxlan vlanvnimap
show vxlan tunnel
```

В выводе `show vxlan tunnel` отображались исходные и конечные IP-адреса туннеля, а также соответствие `VNI 1000 → VLAN 10`.

## Настройка PC1

Первому хосту был назначен IP-адрес `192.168.10.11/24`:

```text
ip 192.168.10.11/24
```

Настройки были проверены и сохранены:

```text
show ip
save
```

Шлюз по умолчанию не задавался, поскольку оба хоста находятся в одной логической подсети.

## Настройка PC2

Второму хосту был назначен IP-адрес `192.168.10.12/24`:

```text
ip 192.168.10.12/24
```

Настройки были проверены и сохранены:

```text
show ip
save
```

## Проверка сетевого взаимодействия

Для проверки связи между хостами с PC1 была выполнена команда:

```text
ping 192.168.10.12
```

На момент проверки хост PC2 оставался недоступен: VPCS выводил сообщение `host (192.168.10.12) not reachable`.

На R1 была проверена таблица MAC-адресов:

```bash
show mac
```

В ней отображался MAC-адрес PC1 на интерфейсе `Ethernet0` в VLAN 10. Это подтвердило, что R1 получает Ethernet-кадры от первого хоста.

Для проверки передачи VXLAN-пакетов по сети Underlay использовалась команда:

```bash
sudo tcpdump -ni Ethernet4 'udp port 4789'
```

Интерфейс `Ethernet4` соединяет маршрутизаторы, а UDP-порт `4789` используется для VXLAN. В проведённом захвате VXLAN-пакеты не были обнаружены, поэтому сквозная передача данных между PC1 и PC2 пока не была подтверждена.

## Сохранение конфигурации

На обоих маршрутизаторах конфигурация была сохранена командой:

```bash
sudo config save -y
```

На каждом хосте VPCS использовалась команда:

```text
save
```

Проект GNS3 также был сохранён.
