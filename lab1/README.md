# Лабораторная работа №1. Установка GNS3 и базовая настройка

## Установка GNS3

Сначала я установила GNS3 и необходимые для его работы компоненты. Для этого я добавила репозиторий GNS3, обновила список доступных пакетов и установила GUI GNS3 и GNS3 Server.

```bash
sudo add-apt-repository ppa:gns3/ppa
sudo apt update
sudo apt install gns3-gui gns3-server
```

После установки запустила GNS3 и выполнила его базовую настройку.

## Загрузка образа SONIC

Для дальнейшей работы в GNS3 я скачала виртуальный образ сетевой OS SONIC.

```bash
wget "https://sonic-build.azurewebsites.net/api/sonic/artifacts?branchName=master&platform=vs&target=target/sonic-vs.img.gz" \
-O sonic-vs.img.gz
```

После скачивания распаковала архив:

```bash
gzip -d sonic-vs.img.gz
```

В результате был получен файл `sonic-vs.img`, который затем использовался для добавления SONIC в GNS3 в качестве QEMU templat'а.

## Настройка uBridge

Для корректной работы сетевых соединений между виртуальными устройствами в GNS3 необходим `uBridge`.

Я дала `uBridge` необходимые права для работы с сетевыми интерфейсами и raw-пакетами без запуска GNS3 от имени `root`:

```bash
sudo setcap cap_net_admin,cap_net_raw=eip /usr/bin/ubridge
```

Также добавила своего пользователя в группу `ubridge`:

```bash
sudo usermod -aG ubridge $(whoami)
```

После этого в настройках GNS3 указала путь до `uBridge`:

```text
/usr/bin/ubridge
```

Для применения новых прав пользователя и обновления членства в группе я перезагрузила компьютер.

После перезагрузки GNS3 смог корректно использовать `uBridge` для организации сетевых соединений между виртуальными узлами.
